## Исправления при проверке

- Тест конкуренции кассира с онлайн-резервированием получил полноценную настройку терминала, сумму наличных и ключ идемпотентности. Теперь проигравший запрос обязан завершиться именно ошибкой вместимости. Ошибка настройки больше не даёт ложный успешный результат теста.
- Новый статус оплаты ограничен кассиром, источником CASHIER и текущей областью доступа; ответы не кешируются. Production-адаптер использует действующую политику ролей: общий доступ только у OWNER. Создан генератор маршрута для точной рабочей сборки.
- Некорректный JSON/хеш в конфигурации терминалов возвращает NOT_CONFIGURED / 503 без раскрытия конфигурации.
- Добавлено объединение полной production Prisma-схемы с таблицей очереди. Сохраняется исходная схема целиком, добавляется только отношение Order.evotorCheckout и модель очереди. Неизвестная контрольная сумма исходной схемы отклоняется.

## До аппаратного теста

1. Собрать единый overlay на закреплённом production-образе: миграции/клиент, маршруты, манифесты, блокировка закрытия смены.
2. Подключить рабочий UI к ожиданию/восстановлению результата вместо ручного подтверждения. Проверить повторное нажатие, обновление страницы и потерянный HTTP-ответ.
3. Подключить самостоятельные продажи корма/фото через ParkOperation без двойного учёта. Обработчик продажи билета с extras не заменяет этот сценарий.
4. Завершить проверяемую процедуру сверки UNKNOWN; не переводить её автоматически в отказ/успех.
5. Получить совместимо подписанный APK. Найденная debug-подпись отличается от установленной; старый ключ пока не найден. Не удалять действующее приложение ради установки без сохранения настроек и сверки операций.
6. Выполнить полный staging-проход с конфигурацией конкретной кассы и обновлённым UI. Подтвердить права проксирования и привязку приложения к устройству.

## Что проверять с Дашей после прохождения этих пунктов

- Наличные: сумма заказа, принято, сдача; один фискальный чек и одна запись CRM.
- Карта: сумма сама появляется на Сбере; успех подтверждается результатом кассы, ручной кнопки «одобрено» нет.
- Отмена/отказ: нет оплаченного заказа и выручки.
- Билет + корм/фото, комбо на два сеанса и товары без билета: правильные строки, места и отчёт.
- Повторное нажатие, обрыв сети, перезапуск, отсутствие бумаги: нет второго списания; неопределённый результат виден и доступен для сверки.
- Обычный рабочий Wi-Fi и раздача телефона, фоновый приём, закрытие смены и сверка итогов.

До выполнения этих проверок обещать готовность к работе без ручного дублирования нельзя.
